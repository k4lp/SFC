# Query Directory Explanation

## 1. Overview
The `src/SalesforceCore/Query` directory contains the heart of the library's "LINQ to SOQL" provider. It allows developers to write standard C# LINQ queries that are automatically translated into efficient Salesforce Object Query Language (SOQL) strings. This abstraction prevents SQL/SOQL injection and provides strong compile-time type safety.

## 2. Key Components

### `SalesforceQueryable<T>`
**Purpose**: This class implements the `IQueryable<T>` interface. It acts as the entry point for LINQ queries. When a developer writes `dataService.Query<Account>()`, they get an instance of this class.
**Function**: It captures the LINQ method calls (like `Where`, `OrderBy`, `Select`) into an Expression Tree instead of executing them immediately.
**C# Concepts**:
- **`IQueryable<T>`**: The standard .NET interface for data sources that can be queried.
- **`IQueryProvider`**: The mechanism that executes the expression tree. `SalesforceQueryProvider` is the implementation here.

### `SoqlExpressionVisitor`
**Purpose**: This class is responsible for translating the C# "code" (Expression Tree) into a text-based SOQL WHERE clause.
**Mechanism**: It inherits from `System.Linq.Expressions.ExpressionVisitor`. It recursively "visits" every node in the logic tree.
**Example Translation**:
- **C#**: `x => x.Name == "Acme" && x.AnnualRevenue > 100000`
- **Visitor Action**:
  1. Visits `BinaryExpression` (&&). Writes `(...) AND (...)`.
  2. Visits Left `BinaryExpression` (==).
  3. Visits Member `x.Name`. Maps to Salesforce field `Name`.
  4. Visits Constant `"Acme"`. Sanitizes and quotes it `'Acme'`.
  5. Result: `(Name = 'Acme') AND (AnnualRevenue > 100000)`

### `SalesforceQueryProvider`
**Purpose**: Orchestrates the execution. When a terminal method is called (like `ToList`, `Count`, or iterating via `foreach`), this provider:
1.  Uses `SoqlExpressionVisitor` to convert the `Where` expressions to SOQL.
2.  Extracts `Select` fields using Reflection or Expression parsing.
3.  Constructs the final SOQL string using `SoqlBuilder`.
4.  Calls `IDataService.QueryAsync` to execute the API call.
5.  Maps the JSON result back to C# objects using `SalesforceMapper`.

## 3. Deep Dive: C# Terminology

### Expression Trees (`Expression<T>`)
At line 22 of `SalesforceQueryable.cs`:
```csharp
private readonly Expression _expression;
```
This is the most critical concept. Unlike a `Func<T, bool>` which is executable code (a delegate), an `Expression` is a **data structure** that represents the code. This allows the library to "inspect" the code (e.g., "Oh, you checked if Name equals 'Bob'") rather than just running it.

### Reflection
Used extensively in `SoqlExpressionVisitor` to read attributes.
```csharp
var fieldAttr = member.GetCustomAttribute<SalesforceFieldAttribute>();
```
This allows the query engine to map a C# property `public string AccountName { get; set; }` to the actual Salesforce API name `Name` (or `Account_Name__c`) defined in the attribute, decoupling the C# model from the database schema.

### Closure Capture
When you write:
```csharp
string region = "West";
var accounts = query.Where(a => a.Region == region);
```
The variable `region` is not a constant in the expression tree; it is a field on a hidden "closure" class generated by the compiler. `SoqlExpressionVisitor.IsClosureAccess` (line 350+) uses Reflection to extract the *value* of `region` ("West") from this hidden class at runtime so it can be embedded into the SOQL string.

### Enumerators & `yield return`
In `SalesforceQueryProvider.ExecuteStreamingAsync`:
```csharp
public async IAsyncEnumerable<T> ExecuteStreamingAsync(...)
{
    await foreach (var record in _dataService.QueryAllAsyncEnumerable(...))
    {
        yield return SalesforceMapper.FromSalesforce<T>(record);
    }
}
```
This pattern allows the library to stream millions of records. As soon as one record is received and parsed, it is handed to the caller. The entire dataset is never held in memory at once.

### Delegates
Used in the `ExpressionVisitor` base class. The `Visit` methods effectively act as handlers for different code structures.
Also used in `SalesforceQueryable.cs` for helper methods:
```csharp
Expression<Func<T, TKey>> keySelector
```
Here `Func<T, TKey>` is a delegate type representing a function that takes `T` and returns `TKey`. Wrapping it in `Expression<>` makes it inspectable.
